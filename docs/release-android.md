# Release Android — Merki

Runbook to build and publish the Android app. The Android build is produced by **EAS Build**
as an **App Bundle (`.aab`)** and uploaded **manually** to the **Google Play Console**.

## Prerequisites

| Item | Value |
|---|---|
| Google Play Developer account | active |
| Package name | `com.merki.app` |
| App in Play Console | created (first release must be created manually) |
| Play App Signing | enabled by Google Play |
| Build | `mobile/eas.json` → `build.production.android.buildType: "app-bundle"` |

## Versioning

Versioning is **automatic**; you do not need to edit versions by hand.

- `mobile/eas.json` sets `cli.appVersionSource: "remote"` and `build.production.autoIncrement: true`.
- Every production build gets a **new `versionCode`** automatically (managed on EAS servers).
- `expo.version` in `mobile/app.json` is the **marketing version** (e.g. `1.0.0`) and stays the same until you change it.

## Icons

Adaptive icon assets (all 1024×1024):

| File | Purpose |
|---|---|
| `mobile/assets/system/android-icon-foreground.png` | mascot on a transparent background (centered, inside the safe zone) |
| `mobile/assets/system/android-icon-background.png` | solid background layer |
| `mobile/assets/system/android-icon-monochrome.png` | themed (monochrome) icon |
| `mobile/assets/system/icon.png` | legacy/source icon |

Configured in `mobile/app.json` under `expo.android.adaptiveIcon` (background `#FFFFFF`).

## Commands (Makefile)

```bash
# Production App Bundle (.aab) via EAS — the usual command
make mobile-aab

# Optional: local, shareable release APK (for manual install/testing)
make mobile-apk
```

Equivalent without `make`:

```bash
cd mobile
npx eas build --platform android --profile production
```

> On macOS, if `make` fails with `You have not agreed to the Xcode license agreements`,
> run once: `sudo xcodebuild -license accept`.

## R8 / code obfuscation (Google Play "DEX optimization")

Google Play scores every upload on **DEX optimization** — Ofuscación / Reducción /
Configuración de R8. Below **25 %** in any category the app can lose visibility
and publishing capabilities; with minification off, Merki scored **1 %** (only
MLKit's pre-obfuscated `zz*` classes counted against the total).

Enabled since `1.0.4` via `mobile/app.json` → `expo-build-properties`:

```jsonc
"android": {
  "enableMinifyInReleaseBuilds": true,
  "extraProguardRules": "…" // keep rules, see below
}
```

> `android/` is generated (`CNG`). **Never** edit `android/app/proguard-rules.pro` or
> `android/gradle.properties` by hand — those are regenerated by `expo prebuild`
> on every EAS build. The `@generated begin/end expo-build-properties` markers in
> `proguard-rules.pro` are where `extraProguardRules` lands.

The rules are **minimal on purpose**: the Play score is lowered by everything R8
cannot obfuscate, so every broad `-keep` costs %. What is already covered by the
consumer rules each AAR ships (verified in `~/.gradle/caches`):

| Ships its own rules (no action needed) | Ships nothing → we add rules |
|---|---|
| react-android 0.83 (`@DoNotStrip`, bridge, turbomodule core, jni, yoga, okio) | `react-native-unistyles` + `react-native-nitro-modules`: their C++ resolves Kotlin classes through hardcoded JNI descriptors (`Lcom/unistyles/UnistylesModule;`, `Lcom/margelo/nitro/…`) → `com.unistyles.**` + `com.margelo.nitro.**` |
| unity-ads 4.21 (`com.unity3d.**`, protobuf, WorkManager, `JavascriptInterface`, its own `-dontwarn`s) | reflection metadata via `-keepattributes` (annotations, Signature, InnerClasses, EnclosingMethod, Exceptions) |
| MLKit text-recognition / common / vision (proto reflection, native methods, `@UsedBy*`) | `-dontwarn com.unity3d.**` (references AdMob/billing classes it does not bundle) |
| expo, expo-modules-core, expo-image (Glide), reanimated, worklets, react-native-svg | |

**Never disable `enableMinifyInReleaseBuilds` again** — every production bundle
must run R8, that is what generates the score Play measures.

### Local release verification (before every upload)

```bash
make mobile-apk VERSION=1.0.x   # regenerates android/ + ./gradlew assembleRelease
adb install -r mobile/android/app/build/outputs/apk/release/app-release.apk
```

- Uninstall the Play build first: the local APK is debug-signed and cannot be
  installed over the store build.
- Smoke test the reflection/JNI paths — these are where R8 mistakes break
  silently in production:
  - **OCR scan** (MLKit)
  - **Unity Ads**: banner + interstitial (`adb logcat | grep UnityAds`)
  - login (email, Google, guest), offline mutation → sync replay
  - SecureStore session restore after force-quit
  - deep link `merki://`, date picker, unistyles-styled screens
- If R8 refuses to compile, see **Troubleshooting** — do not "fix" it by turning
  minification off.

### `mapping.txt` (deobfuscation file) — required with every release

With R8 enabled, Android Vitals stack traces are `a.b.c` frames unless Play has
the mapping file for that versionCode.

1. `mobile/eas.json` → `build.production.android.buildArtifactPaths` uploads
   `android/app/build/outputs/mapping/release/mapping.txt` as an EAS build
   artifact. Download it from the build page on expo.dev (**Build artifacts**).
2. In Play Console, after uploading the `.aab` of the same release, add the
   `mapping.txt` when Play warns *"no deobfuscation file associated with this App
   Bundle"* (it can also be added later from the release / App bundle explorer).
3. The mapping only deobfuscates the versionCode it was built with — always pair
   them.

Deliberately **not enabled yet**: `enableShrinkResourcesInReleaseBuilds`
(`shrinkResources`). RN resolves `require()`-ed PNGs via
`Resources.getIdentifier` at runtime, so the bundled onboarding/profile images
could be stripped by the resource shrinker. To enable later, either verify those
five images render in a release build first, or add a config plugin that writes
`android/app/src/main/res/raw/keep.xml` with `tools:keep="@drawable/*"`.

## Download the `.aab`

1. Open the build page printed by the command (or list builds):
   ```bash
   cd mobile
   npx eas build:list --platform android --limit 5
   ```
2. Copy the **Application Archive URL** of the latest `finished` build, or open the build page on
   [expo.dev](https://expo.dev/accounts/edorguez/projects/merki/builds) and use the **Download** button.
3. You get an **`.aab`** file (e.g. `build-<id>.aab`).

## Upload to Google Play Console (manual)

Current tracks: **Production** (active) and **Closed / Internal testing** — verify `1.0.4+`
minified builds in internal testing before promoting them to production.

1. Go to [play.google.com/console](https://play.google.com/console) → select the **Merki** app.
2. **Test and release** → **Closed testing** (or **Internal testing**).
3. **Create new release**.
4. Upload the `.aab` under **App bundles** (drag and drop, or browse).
   - The first time, accept **Play App Signing** when prompted.
5. **Deobfuscation file (`mapping.txt`)**: Play warns *"no deobfuscation file associated
   with this App Bundle"* — accept the prompt and upload the mappings from the EAS build
   (see the R8 section above for where to download it). Without it, crash reports in
   **Android Vitals** are unreadable.
6. Fill in:
   - **Release name** (auto-filled from the version, e.g. `1.0.4 (8)`).
   - **Release notes** (per language).
7. **Save** → **Review release** → **Start rollout to testing**.
8. Add testers: create/select a **tester list**, add emails, and share the **opt-in URL**.
   Testers install via the opt-in link (not the public Play Store listing).

## Play Console checklist

- [ ] **Data safety**: declare *App activity / Device or other IDs* and "Advertising or marketing" (Unity Ads). Confirm the advertising ID policy.
- [ ] **Content rating** questionnaire: declare that the app **contains ads**.
- [ ] **Target audience and content**: set the age groups.
- [ ] **Privacy policy URL**: `https://somosmerki.app/privacy`.
- [ ] **Store listing**: app icon 512×512, feature graphic 1024×500, phone screenshots, short/full description.
- [ ] **App access**: provide a **demo account** (email + password) or instructions, because login is required.
- [ ] **Ads**: declare that the app contains ads.
- [ ] **Government apps / financial features**: answer as applicable.

## Troubleshooting

| Error | Cause / fix |
|---|---|
| `Version code X has already been used` | That `versionCode` was already uploaded. Build a new one with `make mobile-aab` (it auto-increments). |
| `App bundle was not signed` / signing error | Ensure **Play App Signing** is enabled and the build is a production EAS build (credentials managed by EAS). |
| `Target API level` requirement | Update `expo-build-properties` (currently `compileSdkVersion: 36`) and rebuild. |
| `.aab` not accepted as the first upload | The very first release must be created manually in the Play Console. |
| `make: You have not agreed to the Xcode license agreements` | Run once: `sudo xcodebuild -license accept`. |
| Real ads shown while testing | Dev builds run Unity Ads in test mode (`__DEV__`); production builds always serve real ads. |
| `Missing class detected while running R8` | A library references classes it does not bundle. Open `android/app/build/outputs/mapping/release/missing_rules.txt`, copy the listed `-dontwarn <class>` lines into `mobile/app.json` → `expo-build-properties` → `android.extraProguardRules`, and rebuild. Do **not** disable minification. |
| Runtime crash only in release builds (`ClassNotFoundException`, `NoClassDefFoundError`, JNI errors) | A reflection/JNI-bound class was renamed or removed. Once `mapping.txt` is uploaded for that release, Android Vitals deobfuscates the stacks in Play Console; if the crash is local, get the class name from an unobfuscated rebuild (remove `"enableMinifyInReleaseBuilds"` temporarily) and add a targeted `-keep class <pkg>.** { *; }` in `extraProguardRules`. Broad `-keep class com.**` is not an option. |
| "No deobfuscation file associated with this App Bundle" (Play Console) | Expected with R8 builds until you upload `mapping.txt` for that release — see the mapping section above. |
| Ofuscación still < 25 % in Play Console | The score is per uploaded bundle: only bundles built with 1.0.4+ (R8 on) count. Confirm the DEX panel of the specific release, not the channel average, and upload to internal testing first. |
